<section id="features"><div class="wrap">
  <h2 class="rv">What kiln does</h2>
  <p class="lead rv">Wrap a command, and kiln hashes its inputs. Same inputs, same result, no rerun.</p>
  <div class="grid">
    <article class="cell c1 rv"><h3>Content-addressed caching</h3><p>Results are keyed by file contents, environment variables and tool versions, so a touched timestamp never invalidates anything.</p><code>kiln run -- make test</code></article>
    <article class="cell c2 rv"><h3>Shared remote store</h3><p>Point at any S3-compatible bucket and your whole team reads from one cache.</p></article>
    <article class="cell c3 rv"><h3>Works with what you have</h3><p>No config format to learn. If it runs in a shell, kiln can cache it.</p></article>
    <article class="cell c4 rv"><h3>Explain every miss</h3><p>When a step reruns, kiln prints exactly which input changed.</p><code>kiln why build</code></article>
  </div>
